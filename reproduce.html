Reproduce

Check a release against the public repository

Each release writes a record at /build.json: the commit of our site source, the commit of the public repository that holds the same release, a fingerprint of everything the release deployed, the result line of every gate it passed, the time it shipped and a hash of every served page. The record is signed with our published key.

Check a release against the public repository

curl -s https://indahl.ai/build.json -o build.json
git clone https://github.com/Heuremen-LLC/indahl.ai
cd indahl.ai
git checkout "$(python3 -c 'import json; print(json.load(open("../build.json"))["public_commit"])')"
python3 code/site/accountability.py pages-sha .
python3 -c 'import json; print(json.load(open("../build.json"))["pages_sha256"])'

The two lines printed last are equal when every served page in the public repository is byte for byte the page that release built. The hash is SHA-256 over the sorted list of each page path and its own SHA-256.

Compare the live site with the repository

python3 code/site/accountability.py compare-live .

This fetches each page from indahl.ai and prints any page whose bytes differ from the file in the repository. Pages the server fills at the moment of the request (the weekly page, the transparency counts, receipts read from storage) are listed as filled live and are not compared.

What the release check does not cover

The pages are built from desk data folders that the desk code reads from the public sources each desk names. The repository holds the build code in code/site, the desk code in code/, and the pages it produced. Rerunning a desk reads its sources again on a later day, so a rebuild matches a release where the sources have not changed since. The comparison above needs no rerun. The desk headlines are covered by the kits below.

Reproduce a desk headline

For each desk below, a kit holds the desk's own scoring code, the inputs it read or the list of them with their sha256, and one command that recomputes the headline number and its outcome label offline. Before every release we run every kit in an empty folder from its own contents. The release is refused if a kit does not print the headline it names, if the row our ledger keeps for the desk does not cover that headline (the same label and the number inside the row's interval, or for a desk with no interval the same key fields), or if the live page has moved past it.

Where a source's terms allow it, the kit includes the inputs. Where they do not, the kit lists each input file with its sha256 and the sources to fetch it from, and we rerun the kit on the copies we keep. The live page can move inside the interval between releases. A move outside it or a change of label needs a new ledger row and a new kit.

Desks without a kit

These desks have no kit. The reason and what can be checked are listed for each.

  • CADA: The desk asks public DNS resolvers live whether they block fresh abuse listings. A resolver answer cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the counts and outcomes.
  • HOSTS: The headline is the count at the newest poll of OpenRouter, a live service whose answers cannot be replayed, and its flag test reads the 24 hours before the poll by the clock. We keep each poll as parsed rows, not as the service's answers. Each published copy of the feed has its sha256 on the TAPE chain, so a copy you kept can be checked against what we published. The data pack holds the counts and outcomes.
  • REVISE: The headline compares the first BLS estimate with the most recent value, read from the BLS flat file on each run. The BLS table of first, second and third estimates is kept with its sha256. Until 10 Nov 2026 the flat file was not kept, so the published values cannot be replayed. From the next read on, each version of the flat file is kept by its sha256, and the start of its sha256 is in the feed. The feed names the sha256 of the BLS table it read, and the TAPE chain holds the sha256 of each published feed.
  • TAPE: The headline is a clock, the time since the newest entry was chained. The chain itself can be checked offline. code/tape holds tape.jsonl, every leaves file and tape_verify.py, which recomputes every hash and beacon with no network.
  • TIME: The desk measures public time servers live against a GPS-disciplined clock. A time reading cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the readings and outcomes.
  • UPTIME: The desk probes vendor services and their status pages live from two networks. A probe answer cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the counts and outcomes.

To run a kit, clone the repository and run the command in the desk's folder. The code that makes the kits and the release gate is reproduce/reproduce_kits.py.
