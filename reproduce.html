Reproduce

Check a release against the public repository

Each release writes a record at /build.json: the commit of our site source, the commit of the public repository that holds the same release, a fingerprint of everything the release deployed, the result line of every gate it passed, the time it shipped and a hash of every served page. The record is signed with our published key.

Check a release against the public repository

curl -s https://indahl.ai/build.json -o build.json
git clone https://github.com/Heuremen-LLC/indahl.ai
cd indahl.ai
git checkout "$(python3 -c 'import json; print(json.load(open("../build.json"))["public_commit"])')"
python3 code/site/accountability.py pages-sha .
python3 -c 'import json; print(json.load(open("../build.json"))["pages_sha256"])'

The two lines printed last are equal when every served page in the public repository is byte for byte the page that release built. The hash is SHA-256 over the sorted list of each page path and its own SHA-256.

Compare the live site with the repository

python3 code/site/accountability.py compare-live .

This fetches each page from indahl.ai and prints any page whose bytes differ from the file in the repository. Pages the server fills at the moment of the request (the weekly page, the transparency counts, receipts read from storage) are listed as filled live and are not compared.

What cannot be rebuilt from the repository alone

The pages are built from desk data folders that the desk code reads from the public sources each desk names. The repository holds the build code in code/site, the desk code in code/, and the pages it produced. Rerunning a desk reads its sources again on a later day, so a rebuild matches a release where the sources have not changed since. The comparison above needs no rerun.
