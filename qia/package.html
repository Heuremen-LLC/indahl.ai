QIA Research Package

Heuremen LLC

Check the IBM Quantum calibration record your run depends on, before the run and after it. One download. Your files are opened read-only and never changed. Reports go to their own folder. Run on saved files, the checker sends nothing anywhere.

Download the package (zip) sha256 5cbc890bf10447285465293f97d37074a60f9004399e8c4331711bf0d0209065 · version 1.0.0 · code (git)

Cite: doi:10.5281/zenodo.23874301 (Zenodo)

Before a run

  1. Save the record you are about to run under, or let the checker pull it with your own saved IBM account (needs pip install qiskit-ibm-runtime): python qia_check.py before --pull ibm_kingston
  2. Check it: python qia_check.py before record.json --qubits 0,1,5. It flags T1 or T2 measured more than 24 hours before the record’s stamp, error values of exactly 0, T2 above 2 × T1, and T1 and T2 measured more than 24 hours apart.
  3. Read the Guards before the work: python -m faultsguards guards (PyPI · git).
  4. Measure a T1 and T2 pair yourself in one job: t1t2-check/ prints the QPU seconds before it submits anything.

After a run

  1. Save the record again into the same folder. Keep reports in a different folder.
  2. python qia_check.py after records/ --start 2026-11-01T12:00:00Z --end 2026-11-01T12:40:00Z --qubits 0,1,5 names the latest record in the folder stamped at or before the start, lists every newer record stamped up to the end, and shows each change in the T1, T2 and readout-error figures on your qubits. Times are UTC. If IBM recalibrated between your last saved record and the run, the record in force is not in the folder, so save one right before you submit.
  3. Read the write-up against the Faults: python -m faultsguards faults. Give each reading a check block: check-block/.

What is in it

  • qia_check.py: the before and after checks, Python standard library only.
  • yo/: the reader for YO, our model trained on IBM calibration records. On each run, the exact answer computed by code is printed beside YO’s.
  • faultsguards/: the Faults and Guards package and both PDFs.
  • t1t2-check/: T1 and a Hahn echo T2 on the same qubit in one job, on your account.
  • check-block/: the check block and its commit gate.
  • papers/: A Readout Is Not an Idle.
  • START_HERE.html, README.md, LICENSE.txt, CITATION.cff.

How it was tested

Heuremen LLC, 2 November 2026, on the package as published at https://indahl.ai/qia/qia-research-package.zip

  • Against our mirror's audit code. For the latest published calibration record of each of seven IBM processors (ibm_aachen, ibm_boston, ibm_fez, ibm_kingston, ibm_marrakesh, ibm_phoenix, ibm_pittsburgh), qia_check.py before was compared with the separate audit code that runs our public IBM mirror (https://github.com/Heuremen-LLC/indahl.ai/tree/main/code/mirror). The T2 above 2 x T1 flags, with their outcomes, and the T1 and T2 date-gap flags agreed qubit for qubit on all seven. Both were written by us to the same rules, so this shows the two implementations agree. It does not test the rules themselves.
  • Against 362 saved ibm_kingston records. The before checks were recounted with separate code, and every count agreed on every record.
  • On a real run. Our Darkwave kit test jobs ran on ibm_kingston from 01:11 to 01:17 UTC on 2 November 2026, and each job saved the calibration record it ran under. qia_check.py after, given the six records our mirror saved that evening, named the same record (stamped 00:39 UTC) and reported no record stamped during the run. No record was stamped in that window, so the part of the check that lists records stamped during a run was exercised on test files only, not on this run.
  • The pull path. qia_check.py before --pull ibm_kingston saved the live record from IBM and checked it. The saved file was unchanged after the check (sha256 before and after equal). Our test passed our own IBM connection in place of a saved account. The saved-account step itself (QiskitRuntimeService with no arguments) is IBM's own code.

Not yet tested inside this package: the YO reader (yo/yo_audit.py) against the model. YO itself is scored against the exact code answer on held-out IBM records at https://indahl.ai/iris/lab
