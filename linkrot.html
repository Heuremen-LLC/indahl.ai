Division: HERMES

This page reads links two ways. The first part reads every arXiv paper in five categories that states where its code is. The second part reads random samples beside it: early web listings, addresses cited in standards and in official documents, landmark sites of the early web and our own name (samples beside arXiv).

Papers state where their code is. Does the link still lead there?

We read every arXiv paper in five categories whose abstract points to GitHub, GitLab, Hugging Face, Zenodo or Bitbucket, and keep each link the abstract or the arXiv comment gives. Every link is requested and read again every seven days. A link counts as rot when the page is gone or the host name no longer exists. A host that blocks us or times out is counted apart and is never rot. Every link is also requested from an independent network, the GitHub runner network, and a link that one network reads live and the other reads gone is counted as blocked and never as rot.

Ten control links run before each pass, five that must be live and five that must be gone. If any control reads wrong, every row reads cannot tell. For links that lead to a GitHub repository we also ask whether anything is there: the repository check below counts repositories with no commits. We do not read the code. Links that appear only in the full text of a paper are not reached. Rules were committed before the first link was checked.

Above: the lower end of the 95 percent interval of the rot share is at or above 5 percent. Consistent: the whole interval lies below 5 percent. Cannot tell comes with a reason beside it. TOO_WIDE_TO_RESOLVE means fewer than 30 links are readable or the interval holds both zero and 10 percent, which is the size that matters. STRADDLES_EDGE means the interval overlaps the 5 percent edge. NO_INTERVAL_FORMABLE means a control failed or no link is readable. The rule moved to Standards 2.0 on 12 November 2026 by a plan addendum, and earlier readings stand under the rule they named. REQ-13: links that read blocked or timed out are the nothing returned count and sit outside the share. Source: the arXiv API.

Beyond arXiv: early web links, standards and official documents

The arXiv census above is one sample. Beside it we read random samples of addresses from the early web and from documents that cite the web: the monthly What’s New column at NCSA from 1993 to 1996, the final Open Directory listing of March 2017, the reference sections of RFCs, and Federal Register documents. For each address the stated side is the address as it was listed or cited. The delivered side is what answers there today. Each sample was drawn with a public random seed after the rules were committed, and no address was chosen outside the draw.

Every address gets exactly one state. It answers with the same content as its earliest capture in the Wayback Machine, answers with changed content, or answers with no capture to compare. It sends readers to a different domain. It shows a parking page or a sale listing. Its robots.txt asks automated readers not to read it, and we do not. Its name no longer resolves, it refuses the connection, it answers with an HTTP error, or it does not answer in time. When our own checker fails, the address reads as our failure and is read again on the next pass. It never counts as gone.

The median interval is the distribution-free 95% interval from order statistics.

Repeat floor

Every address whose draw key begins with 0, 1 or 2 is read a second time, at least three hours after its first read, by the same code and against the same stored capture. Each sample is the smallest keys of a much larger list, so this takes every address in the NCSA, Open Directory and Federal Register samples and most of the RFC sample. 73 of 2,685 addresses read twice changed state between the two reads (2.7%, Wilson 95% interval 2.2% to 3.4%). The parking detector, read in full
