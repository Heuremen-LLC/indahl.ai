MODEL Data Pack

Heuremen LLC

Download (zip) sha256 4f4af44de6aa849b3b190e69cbaabfa1f554dcb3e198d6839b3b5d6697a59b4b · code (git)

Cite: doi:10.5281/zenodo.23874310 (Zenodo)

The data behind the MODEL page at https://indahl.ai/hermes/model, as files you can open in a spreadsheet or Python. MODEL sets what AI hardware vendors state about their systems next to the results MLCommons publishes. Each file comes as the page publishes it, and each JSON file also comes as CSV with one row per record. The statements were fetched and compared on 2026-10-28, the files were built on 2026-10-28, and the MLCommons files were retrieved on 28 October 2026. Vendor pages and MLCommons files change, so a later read can differ.

What is in each file

Statements and outcomes (json/claims.json): 531 statements from 74 sources, each with an outcome of ABOVE, BELOW, CONSISTENT or CANNOT_TELL. The file has a summary entry and a claims list. The rows come as csv/claims.csv. The columns are id, vendor, source_key, statement, verbatim, compared, stated, in_file, outcome, note, label_mismatch and four columns that start with source_, which hold the title, address, fetch date and round of the page the sentence comes from. The id repeats between sources, so a row is named by source_key and id together. The statement column holds the sentence as published, without quotation marks. The page puts it in quotation marks when verbatim is true. The compared column names the MLCommons entries the statement points to, such as 5.1-0072, and the in_file column gives what the files show. In 2 rows label_mismatch is true, and the in_file text of those rows says how the label in the file differs from the label in the statement. For those rows the page adds one sentence to the note, which reads: The entry named in the post is listed in the file with a different accelerator or model.

The summary comes as five more files. csv/claims_sources.csv has one row per source with its vendor, title, address and round. csv/claims_tally.csv has the number of statements per source and outcome, and a blank means none. csv/claims_vendor_page_hash.csv has the SHA-256 of the vendor page as we read it. csv/claims_mlcommons_files.csv has the address, SHA-256 and row count of each MLCommons inference file we used. csv/claims_meta.csv has the remaining summary fields as key and value, such as the build date and the commits of the training and storage repositories.

Results by accelerator (csv/accelerators.csv and json/accelerators_summary.json): 1,727 closed-division datacenter throughput results from MLPerf Inference v5.0, v5.1 and v6.0 that have an accelerator count, in 569 groups of version, model, scenario and accelerator. The per_accelerator column is result divided by total, which is our own computation and not an MLPerf primary metric. The summary file gives the number of submissions and submitters, the minimum, median and maximum, and the entry with the highest value for each group. csv/accelerators_summary.csv holds the same groups as CSV. The page states which rows are left out and why.

Storage results (json/storage_v30_results.json): 144 rows that aggregate the MLPerf Storage v3.0 result files into one row per system and workload, where for training the value is the mean of the runs after the first, as csv/storage_v30_rows.csv, with the source and licence in csv/storage_v30_meta.csv. Rows for different workloads have different measurement columns, so a column is blank where the workload has no such measurement.

Readings from our unit (json/mac_run.jsonl): 17 lines of memory bandwidth readings from the MacBook Pro 14-inch with M5 Max that the Apple table on the page uses. Each line has a kind. They come as csv/mac_run.csv, where a column is blank for a line of another kind.

Sources and dates

SOURCES.md lists the upstream sources, their links, their terms and the dates found in the data. NOTICE.txt carries the MLCommons attribution and trademark lines. The statements were fetched on 2026-10-28. The MLCommons files were retrieved on 28 October 2026. Every row of csv/claims.csv carries the address of the page its sentence comes from and the date it was fetched.

How to open the files

Spreadsheet: open any file in csv/. The files are UTF-8, and the ones we wrote carry a byte order mark so Excel reads names correctly. Empty text and missing values are both shown as blank cells. The file csv/accelerators.csv is the published file without a byte order mark.

Python, standard library only:

`` import json, csv claims = json.load(open("json/claims.json", encoding="utf-8"))["claims"] rows = list(csv.DictReader(open("csv/claims.csv", encoding="utf-8-sig"))) acc = list(csv.DictReader(open("csv/accelerators.csv", encoding="utf-8-sig"))) ``

Check the pack with python verify.py. It recounts the rows of every file, compares every CSV cell with the JSON, recomputes the outcome counts of each source from the statements, and recomputes every group in accelerators_summary.json from the rows of accelerators.csv.

Notes on the data

The files in json/ are the files the MODEL page links, unchanged. The page also links the scripts that recompute each row from the MLCommons files, and those scripts are not in this pack. They are in the code folder at https://github.com/Heuremen-LLC/indahl.ai.

The papers table on the MODEL papers page and the live model-claim rounds are not in this pack. The papers table has no data file, and the live rounds are a feed that the page reloads every 30 seconds.

How it was tested

On 2026-11-01 the zip was unzipped into an empty folder and every CSV was opened with pandas 3.1.0 on Python 3.14 at default settings. The live MODEL page and its 74 source pages were fetched the same day and read with lxml 6.1 and Beautiful Soup 4. Every count and number below was compared with the live pages and matched, except the one note named further down.

  • Live files: claims.json, accelerators_summary.json, storage_v30_results.json, mac_run.jsonl and accelerators.csv are byte for byte the files in the pack
  • Statements: 531 rows in 74 sources, with 8 ABOVE, 51 BELOW, 368 CONSISTENT and 104 CANNOT_TELL, which are the sums of the source table on the page
  • Source table: vendor, round and the four outcome counts of all 74 rows equal claims.csv recounted with pandas and claims_tally.csv
  • Source pages: the sentence, compared, stated, in the file, outcome and note of all 531 statements, and the line N statements checked of each of the 74 pages
  • Results by accelerator: 1,727 rows in 569 groups, 814 in v5.0, 493 in v5.1 and 420 in v6.0, and per_accelerator equals result divided by total in every row
  • Left out rows: no accelerator count 49, 61 and 24, and latency units 6, 0 and 7, for v5.0, v5.1 and v6.0
  • MLCommons files: rows 17,454, 1,448, 520 and 492 for v5.0, v5.1, v6.0 and v6.1, with the first 16 characters of each SHA-256 as the page prints them
  • Training and storage: result sets 229, 201 and 185 with commits eabf23a07b2a, d7e703fccc1c and 441d65f4445c, and 144 storage result rows with commit 802035fe6580
  • Known answer: entry 5.0-0001, llama2-70b-99, Offline, 33,928.1 tokens per second on 8 accelerators is 4,241.0125 per accelerator
  • Known answer: the statement NVIDIA v5.1 C1 reads +45.2% and CONSISTENT, and 5.1-0072 over 5.1-0071 for DeepSeek-R1 Offline recomputes from accelerators.csv as 1.452

The id column repeats between sources, with 500 different values over 531 rows, so a row is named by source_key and id together, and that pair is unique.

The test found one note, Nebius Storage v3.0 with id NB11, worded differently in the published claims.json than on the page. The published file was corrected on 2 November 2026 to match the page, and this pack carries the corrected file.

For the rows with label_mismatch true, the page adds the sentence The entry named in the post is listed in the file with a different accelerator or model. to the note. The pack does not repeat it in the note column.

At default settings pandas reads a blank cell as missing. In csv/claims_tally.csv a blank means no statement with that outcome. No cell in any file is text that pandas reads as missing, such as NA or None.

The file verify.py compares every CSV cell with the JSON, recomputes the outcome counts of each source from the statements, and recomputes every group of accelerators_summary.json from accelerators.csv.

Not tested: Excel or LibreOffice, the scripts that recompute the rows from the MLCommons files, and a new download of the MLCommons files. The page prints the first 16 characters of each SHA-256 and the pack holds the full values, and those were compared, but the files were not downloaded again.
