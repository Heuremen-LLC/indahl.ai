VAULT · Receipts and Sealed Files

Division: HERMES

Your file never leaves your computer. Your browser hashes it, seals it or opens it, and the only thing ever sent to us is a 64-character hash, and only when you press a receipt button. We keep the hash and the time. We do not keep, scan, host or release any file.

Get a receipt

A receipt proves that a file with this hash existed by this time. It joins the tape within the hour. It does not show who made the file or that it is true.

Check a receipt

Seal a file until a date

Your browser encrypts the file to a future round of drand, the public randomness beacon run by independent organizations. The key for that round does not exist until drand publishes the round, so nobody can open the file before then. Not you, not us, not drand. After it, anyone holding the sealed file can open it. The sealed file is saved to your computer. Keep the original, because a lost sealed file cannot be recovered.

Open a sealed file

What this does and does not do

We never receive the file, the sealed file or a key. We cannot scan, host, find or release your file, and nothing here can be used to take it back. If you share a sealed file, you are the one sharing it. Do not seal material that is illegal to hold or share. We cannot see it, and the law applies to you and to anyone you pass it to.

We store the hash and the time of each receipt. We do not store your network address, and our network provider keeps its own logs. Release times come from drand, so they do not depend on us. If drand ever stopped publishing, a file sealed to a later round could not be opened. Files over 60 MB are refused.

The code that runs here is in the repository. Sealing uses tlock-js (npm), bundled into one file served from this site.
