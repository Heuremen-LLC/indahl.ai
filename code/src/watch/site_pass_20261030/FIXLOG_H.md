## H-12 airq (urgent): fixed
Root cause found and checked against the live service. The key and the points were fine (organization call 200, 789,214 points left, 90 of the 147 sensors reporting now). The history service returns only the averaging buckets that are complete inside [start, end]. A bucket labelled with a day needs end at or after the next midnight, an hour bucket needs end at or after the next hour. Test on sensor 266321: window [11:00, 11:59:59] returned nothing, [11:00, 12:00:00] returned the 11:00 bucket, day window ending 23:59:59 returned nothing and ending at midnight returned the day. The code ended every call at 23:59:59 (days) or +3599 s (strip), so each call lost its last bucket. The first run (29 Oct 18:51 UTC) lost 28 Oct, every later day was then asked alone and came back empty, and line 96 had already written `sens[day] = {}` so nothing was ever asked again. The strip had a second cause: the AirNow file for the newest hour is posted part filled (4 of our 147 monitors eight minutes after the hour, 95 to 105 when whole) and the code took the first non-empty file.
