## Method facts (what we do, not what tools we use)
1. Stated against delivered: an organisation's own stated figure is set against the record of what was delivered, and no cause is named for a gap.
2. Four outcomes, never folded: ABOVE, BELOW, CONSISTENT, CANNOT_TELL. Thresholds are fixed before the first read, and nothing returned is counted apart.
3. Plans before data: plans are public and committed first. A rule set after the data is labelled on its row, and the original reading stays beside it.
4. One ledger for every public number: 2,772 rows (2,730 live, 38 withdrawn with their history). Every headline writes a value row, and on 10 Nov about 2,400 snippets were matched to the live pages.
5. Receipts and a tape: feeds and changed pages are hash-chained about every half hour and stamped with OpenTimestamps. Every study read carries a receipt, and VAULT issues file-hash receipts.
6. Second seats and referees: an outside runner checks pages byte for byte (45 of 45 match). A second script that shares no code recomputes the counts, and referee review happens before shipping.
7. Corrections in public: every page has a Respond link and a correction form. For example, QIA re-read 24 runs and printed that 289 of 1,043 calls withdrew.
8. Data packs: every desk is a zip with its README, sources and tests that match the page counts. There is also a key-free API and MCP endpoint. Search is allowed and training use is not.
