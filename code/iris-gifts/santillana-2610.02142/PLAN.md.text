# Gift plan: arXiv 2610.02142 (J. S. Santillana, "Keyword Harnesses Fail Open"), written 31 Oct 2026 before any model run

Scout recount (scout/RECOUNT.md, scout/reproduce.sh, our code, files read as data): the corpus counts, parameter counts, section 6.6 drift
figures and printed arithmetic rebuild except the rows the recount lists as NOT REBUILT. Weights are read with scout/pt_safe.py (a
restricted unpickler that runs nothing from the file). His code has no license, so the decoder below is our own, written from the
architecture as described in his model file (RMSNorm pre-norm, SwiGLU, RoPE theta 1e6 rotate-half, no RoPE on every fourth layer, GQA,
tied embeddings).

## Live arm L: his verbatim protocol on the 269 corpus rows, CPU fp32 greedy, our code
- Rows: tool_sft_mini_v1.jsonl (sha256 c0eb6e90), distinct user prompts with first occurrence kept, rows whose tool is outside the five
  declared tools dropped (scout/corpus_counts.py rule A): 269 rows, 247 expect a call and 22 expect none.
- Prompt: the row text up to and including <|assistant|>, tokenized with his tokenizer.json (sha256 462efac1), no BOS (his training
  view encodes the text without one). Special tokens must encode to their single ids (<|system|> 4, <|user|> 5, <|assistant|> 6, <|end|> 7).
- Models: 600M step 154,000 (vectrayx-600m-checkpoints, sha256 90e40590), the pre-remediation 1B parent (phase4a_v0_real_llm, 2c5b7f01) and
  the repaired 1B child (text_diag_repro_v0 step 2,202, 207808179f, stored in bf16 and upcast exactly to fp32). Each loads with every tensor
  used and none missing.
- Decode: greedy (argmax) in fp32 on the Mac CPU with PyTorch 2.4.0, torch threads fixed at 6, no repetition penalty, stop at <|end|> or
  </s>, at most 256 new tokens (his maximum is unstated; the cap and every completion length are recorded). Two repeats per model.
- First-token probe: P(token 8, <|tool_call|>) at the position after <|assistant|>, per row, from the same forward pass.

## Known-good before readings (KNOWN-GOOD)
KNOWN-GOOD: the repaired child on its own corpus. His paper prints 0.959 well-formed and 0.988 exact copies among them; a decoder with a
wrong forward pass cannot recite training completions token for token, so a child exact-copy rate far below his means our code is wrong
and the arm stops before any other reading. Also: tokenizer special ids as above, and parameter counts equal the scout's (661.6M, 1,041.9M).

## Scorer (his section 5.3 as printed, our code)
Well-formed: the completion holds <|tool_call|> followed by a JSON object with a string "name" and an object "args", closed by
<|/tool_call|> or the end of the completion. Exact: the call text equals the row's training completion call byte for byte. No-call rows
pass suppression when no <|tool_call|> is emitted.

## Readings (four outcomes, per model)
L1 Well-formed emission over 269 rows with Wilson 95%, against his 0.926 (600M), 0.100 (parent), 0.959 (child); and over the 247
   call-expecting rows separately.
L2 Exact copies among well-formed calls, against his 0.235 (600M) and 0.988 (child), with the counts.
L3 Repeat floor: rows whose completion token ids differ between our two repeats.
L4 First-token probe: median and range of P(<|tool_call|>) per model over the 247 call rows.
L5 Our counts beside his printed denominators (238 and 246 among well-formed calls, 5 parseable calls for the parent), to see which
