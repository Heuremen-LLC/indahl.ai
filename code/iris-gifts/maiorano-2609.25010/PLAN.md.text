## Addendum 1 (30 Oct 2026, after M1-M4 were computed; M2b is defined after the data)
Reading compute_validity.py's analyze() shows that a package whose tau is None (every pair tied) is left out of the tau mean and its
bootstrap, while n_packages counts it, and top-1 and lift keep it. So M2 can tell how the 71 all-tied baseline packages enter: they leave
the baseline's tau. M2b gives the baseline's tau mean with those packages counted as 0, by arithmetic on his printed mean and counts
(0.361 over 398 - 71 packages), beside the panel's 0.084. This assumes the None packages are exactly the all-tied ones, which holds when no
package has every real CTR equal (his lift code drops such packages, and the reading counts them from replication.json n).

## Addendum 2 (30 Oct 2026, after the referee pass; M2c and M3b are defined after the data)
Corrections from the referee: M2b's reason in Addendum 1 is wrong. A package enters the reliable-winner set only when its top CTR is
strictly above every other variant, so every pair with the top variant has a real difference, and tau is None only when every prediction is
equal. The 71 come from a tie rate computed after rounding scores to six decimals, so the None count is at most 71, and the release does not
give the panel's count. The 0.361 in Table 1 also equals analyze_replication.metrics() output, which applies the same rule. M2b is a
sensitivity, not a correction. New readings, each defined after the data:
M2c the same exclusion for Spearman rho: 0.350 with the 71 counted as 0, by the same arithmetic.
M3b the seed in the GPT-4.1 rerun: whether scripts/tier2_crossmodel.py sends a seed, beside the paper's "all seeds are pinned and recorded
per prediction" (Internal validity) and the seed rule in the protocol appendix.
