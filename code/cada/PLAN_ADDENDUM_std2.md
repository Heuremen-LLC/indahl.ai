# CACA plan addendum for Faults and Guards 2.0

Dated 12 November 2026. Written before any reading under the 2.0 outcome rule.

## What this addendum changes
Only the promise of an outcome word and what is printed beside the readings. The feeds, the sampling, the resolvers, the queries, the checkpoints, the alive and blocked rules, the Wilson interval and the notes and correction of the plan are unchanged. Data, sources and tests are unchanged. Readings recorded before this date stand under the rules they named.

## The decision on provider-stated numbers
The Outcomes section of the plan promised ABOVE, BELOW or CONSISTENT against a number a provider states, and CANNOT_TELL where none is stated. The code never assigned an outcome, and the correction of 30 October 2026 records that no provider statement has been collected and that no row carries an outcome word. Two honest options exist. One is to collect provider statements and name a band before reading them. The other is to remove the outcome promise. The smaller honest option is the second, because collecting statements needs fetching and reading provider pages that this desk has not read, and a band named now for numbers not yet seen would be a guess. This addendum removes the promise.

From this date no cell of this desk carries an outcome word. A cell is a measured share of alive listed domains that a filter refused at one checkpoint, with a Wilson interval at 95 percent, published as measured. It is a description and not a reading against a stated figure. The share is not compared with any provider claim.

## If provider statements are collected later
A new addendum, dated before the first such read, must quote the statement verbatim with page and date, name the figure and the band or tolerance, name the size that matters if the reading is a departure from a null, name the edge convention, and keep the Wilson interval at 95 percent unless it names another method. Until then the outcomes of this desk are not assigned. If the standard were applied to the unread claim, a provider that states no number would read CANNOT_TELL with reason NO_INTERVAL_FORMABLE for every cell, which says no more than the removal does.

## Failed reads
A query that returns no answer is a failed read. The plan's Note 2 already counts it apart as a timeout and keeps it out of the denominator. Under 2.0 each timed-out query is a NOTHING_RETURNED, listed apart and outside any numerator or denominator. A cell with no answered query is listed as a cell that returned nothing.

## Beside the table
The summary and the page print the REQ-13 line. It gives the count of NOTHING_RETURNED, which is the timed-out queries, and the share of CANNOT_TELL split by reason, which is none of none because no outcome is assigned. It also gives the count of cells that hold a share and the count of cells that returned nothing.

## Dead zone closed
The dead zone the audit names, a plan that promises outcomes the code never assigns, is closed by the removal above.
