# LINKROT: "code and data are available at" against whether the link works. Plan, written before any link is checked.

## Claim read
A paper states, in its abstract or arXiv comment, that its code or data can be found at a URL. Stated: the link leads there. Delivered: the link resolves now, and whether it still resolves a week later.

## Population (a census, no sampling)
arXiv API, public. Papers in cs.LG, cs.CL, cs.CV, quant-ph, stat.ML whose abstract matches one of the tokens github, gitlab, huggingface, zenodo, bitbucket (the search side), and from whose abstract plus arXiv comment text we extract URLs on those five hosts. Papers whose link is only in the full text or only in the comment and not in the abstract search are not reached. That is a stated limit. Cohort = year of first submission, 2018 to 2026 (2026 partial). A unit is one unique link per paper.
GitHub and GitLab links are cut to https://host/owner/repo (first two path parts). Trailing punctuation is stripped.

## Check (fixed now)
One request per link, HEAD then GET if HEAD is refused, follow redirects, 20 second timeout, user agent naming this site, one request per host at a time with a pause. Status:
LIVE: final status 2xx.  GONE: 404, 410 or 451.  DNS_FAIL: the host name does not resolve.  BLOCKED: 401, 403, 429, 5xx or a refused connection.  TIMEOUT.
BLOCKED and TIMEOUT are counted apart and are never rot. A redirect that ends on a different owner or repo name is LIVE and also counted as MOVED.
Rot share = (GONE + DNS_FAIL) / (LIVE + GONE + DNS_FAIL), per cohort and per host, Wilson 95% interval.
Outcome against the claim that the link leads there (zero rot): ABOVE if the lower end of the rot interval is above 0.10. CONSISTENT if the upper end is below 0.05. Otherwise CANNOT_TELL. A cohort with fewer than 30 readable links is CANNOT_TELL. Thresholds fixed here.
Re-check: every link is read again every 7 days, so each link has a history and the cohort shares have a time series. A link that was GONE and reads LIVE later is counted as returned.

## Known-good gate
Before each full pass, 5 links that must read LIVE (github.com/torvalds/linux, www.python.org, arxiv.org/abs/1706.03762, example.com, zenodo.org) and 5 that must read GONE or DNS_FAIL (github.com/this-owner-does-not-exist-7q2/none, example.com/no-such-page-7q2, a made-up .invalid host, zenodo.org/records/1 does not count, raw.githubusercontent.com/torvalds/linux/master/no-such-file-7q2). If any control reads wrong, the pass is CANNOT_TELL for every cohort and the page says the instrument failed its gate.

## Not claimed
Whether a live repository holds what the paper says. Whether a GONE link was removed by the author. Hosts that block us are not rot. Papers not in the five categories or without a link in the abstract are not part of the population.

## Seats
This plan covers one seat (this Mac). A second seat from the independent runner network is added by a dated addendum before it is used, and a disagreement between seats on a link reads BLOCKED.

## Addendum 2 (29 Oct, before the second seat was used)
The second seat from the independent runner network is added, as the plan's Seats section allows. Every link in the list is also requested from the GitHub runner network (the nodes repository, workflow linkrot-probe, one pass every 7 days, results committed to data/linkrot/results.jsonl) with the same classification, the same controls and the same per-host pause as the first seat.
Combining the seats (fixed now): a link with a reading from both seats within 14 days of each other reads LIVE if both read LIVE, and GONE or DNS_FAIL if both read that. If one seat reads LIVE and the other reads GONE or DNS_FAIL, the link reads BLOCKED and is counted as a disagreement, never as rot. Any other combination of two readings (for example one seat BLOCKED or TIMEOUT) keeps the first seat's reading. A link with a reading from one seat only keeps that reading. The page shows the number of disagreements and the number of links read by both seats.
The runner's controls are the same ten links. If any control reads wrong in a runner pass, the whole pass is discarded and the links keep their first-seat readings.
No threshold, class or outcome rule changes.

## Addendum 3 (9 Nov 2026, written before any link in these samples was checked): samples beside arXiv
The arXiv census above stays as it is and becomes one sample among several, so that no single group of authors carries the reading. The new samples read early web links, links cited in standards documents and in official documents, and the indahl domains themselves. For every sample the stated side is the address as it was listed or cited, and the delivered side is what answers at that address today. Code: early/linkstate.py (one address, one state), early/gate.py (the gate), early/frame_ncsa.py, early/frame_dmoz.py, early/frame_rfc.py, gov/frame_fedreg.py, early/early_tick.py, ownname/ownname_tick.py.

### Draw rule (every sample)
Each unit gets the key SHA-256 of seed, sample name and unit id. A sample is the units with the smallest keys, and links are read in key order, so a partial pass is itself a random draw. The seed is the randomness of the first round of the drand default chain published after this addendum is committed, written with its round number to data/early/seed.json. No unit is added or removed by hand.

### Samples (fixed now)
E1, NCSA What's New, 1993 to 1996. Frame: every monthly page whats-new-MMYY.html under www.ncsa.uiuc.edu/SDG/Software/Mosaic/Docs/old-whats-new/ that the Wayback Machine holds as a 200 text/html capture, each read at its earliest capture. Addresses: every link on those pages, http and https only, minus the Mosaic documentation tree (http://www.ncsa.uiuc.edu/SDG/Software/Mosaic/), which holds the column's own navigation. Gopher, ftp, telnet, wais and file links are counted and left out. Unit: one distinct address. Era: 1993 to 1996, with the month of first listing kept. Draw: 500 units.
E2, the final Open Directory (DMOZ) dump. Frame: every ExternalPage address in content.rdf.u8.gz generated on 12 March 2017, the last capture of that file in the Wayback Machine (capture 20170312160530, SHA-1 digest FATJCOXLKJQAL5DL5IMCVQ75SWEXFXLQ, checked on download). Unit: one distinct http or https address. Draw: 1,500 units. Era: the year of the address's earliest 200 capture in the Wayback Machine, in the bins 1996 to 2001, 2002 to 2008 and 2009 to 2017, plus a row for addresses with no 200 capture before 13 March 2017. Era sizes are whatever the draw gives.
E3, addresses cited in RFCs, 1993 to 2017. Frame: every RFC published 1993 to 2017 per the RFC Editor's rfc-index.xml, read as plain text. Only reference sections count: from a heading at the left margin whose words are References (optionally numbered, optionally Normative, Informative, Non-Normative or Informational) to the next heading at the left margin, with page headers, page footers and form feeds removed first. Addresses in angle brackets are joined across line breaks. Example and reserved hosts (example.com, example.net, example.org, .example, .invalid, .test, localhost) are dropped. Unit: one distinct address. Era: the year of the earliest RFC that cites it, in the bins 1993 to 1996, 1997 to 2001, 2002 to 2008 and 2009 to 2017. Draw, per era: 150 units among addresses on other hosts and 50 among addresses on IETF and IANA hosts (rfc-editor.org, ietf.org, iana.org, iab.org, irtf.org, iesg.org, isoc.org, internetsociety.org), reported apart, because later RFCs cite other RFCs through rfc-editor.org addresses. An era with fewer units gives all of them. The frame holds 18 addresses for 1993 to 1996, so that era is shown with its counts and marked too few to read as a share.
G1, addresses in Federal Register documents, 1995 to 2017. Frame: every document the federalregister.gov API returns for the search term "http", published 1995 to 2017, listed month by month so no query reaches the API's result cap. Eras by publication date: 1995 to 1996, 1997 to 2001, 2002 to 2008 and 2009 to 2017. Draw, per era: documents in key order. A document's addresses are the links in its raw text, minus the delivery header line ("From the Federal Register Online via") and example hosts. A document with no address is passed over and counted. The first 150 documents with an address form the sample, and from each the one address with the smallest key is drawn. The unit is the document's drawn address, so an address drawn from two documents is read once and counted for each.
N1, our own name. Frame: indahl followed by each ending on this fixed list: ai, com, net, org, io, co, dev, app, us, uk, co.uk, de, no, se, dk, fi, is, nl, be, at, ch, eu, fr, it, es, pl, ca, au, nz, info, biz, me, xyz, tech, online, site, store, cloud, tv, cc. Every name is read, with no draw. Address read: http://indahl.<ending>/. The page lists indahl.ai first and the rest in alphabetical order of the ending. Registration: RDAP through the IANA bootstrap file, keyless, read for registered or not and for the expiry date when the registry publishes one. For endings with no RDAP service in the bootstrap file (io, co, us, de, se, dk, eu, ch, it, es, nz, me, be, at), registration reads from DNS delegation (NS records for the name) and the table says so. No registrant, owner or contact data is kept in our files or shown.
L1, landmarks of the early web. Its list rule is a separate addendum, committed before any landmark is read.
Wikipedia external links are not sampled here, because a separate Wikipedia read is under way. They are a possible later sample.

### States (fixed now)
Each address gets exactly one state, decided in this order. The first rule that applies is the state.
1. NOTHING_RETURNED: our checker failed. Both resolver services unreachable, the system resolver failing where DNS over HTTPS answered, an IPv6-only host read from this seat (it has no IPv6 route), the Wayback Machine unreachable when a live page needed its baseline, or an error we did not anticipate. Retried on the next run. Never rot.
2. DEAD_DNS: the host name has no address (NXDOMAIN, no A or AAAA record, or SERVFAIL from both resolver services).
3. PARKED_OR_FOR_SALE: the parking detector fires (below).
4. ROBOTS_DISALLOWED: the host's robots.txt disallows our reader for this path, or robots.txt answered 5xx, which RFC 9309 asks readers to treat as disallow. The page is not requested.
5. REDIRECTED_ELSEWHERE: the listed address answers with redirects that end on a different registered domain (ICANN section of the Public Suffix List), whatever answers there.
6. DEAD_CONNECT: the host name resolves but no HTTP answer comes back (connection refused, reset or closed without a response, host unreachable, or a TLS handshake that fails even without certificate checks).
7. TIMEOUT: no answer within 20 seconds for a step, or 45 seconds for the whole page.
8. DEAD_HTTP: the host answers HTTP on its own registered domain but the final answer is not a 2xx page (a 4xx or 5xx status, a redirect loop or more than 10 redirects, or another non-2xx status). Shown with its split: 404 or 410, 401 or 403 or 429 (which can be a refusal of automated readers rather than a missing page), other 4xx, 5xx, and redirect loops.
9. LIVE_NO_BASELINE: a 2xx page on the same registered domain, and the Wayback Machine holds no readable 200 capture of the address.
10. LIVE_SAME: a 2xx page on the same registered domain that matches the earliest 200 capture: identical bytes, or a Jaccard index of at least 0.80 between the sets of 3-word shingles of the visible text of the two pages (the markup tokens when either side has fewer than 20 words). Non-text content is compared by bytes only.
11. LIVE_CHANGED: a 2xx page on the same registered domain that does not match the earliest 200 capture.
The brief named eight states. Three were added so the bins cover every case without a catch-all: a live page that was never captured cannot be called same or changed, a host that refuses the connection gives neither a status nor a timeout, and we do not request pages a host's robots.txt asks us not to read. The summary also shows how many live pages would read same at 0.50 and at 0.95, a sensitivity read fixed now.

### Check (fixed now)
User-Agent "HeuremenLLC-linkrot/1.0 (https://indahl.ai)", no email anywhere. DNS over HTTPS (Cloudflare, then Google). robots.txt per RFC 9309: product token HeuremenLLC-linkrot, our own group if present or else the * group, longest match wins with allow winning a tie, * and $ honoured, 4xx means allow, 5xx means disallow, up to five redirects. One request at a time per host, at least 1.2 seconds apart. Up to 10 redirects and 2 MB per page. A certificate that fails verification is read anyway and recorded. The Wayback Machine is asked one request at a time, at least 1.1 seconds apart, with a 60 second pause on 429 or 503. Baseline: the earliest 200 capture of the listed address, read raw.

### Parking and sale detector (fixed now, early/linkstate.py)
Three signal families, and any signal makes the state PARKED_OR_FOR_SALE. (a) The registered domain's name servers end in a parking or marketplace name-server domain on a fixed list. (b) Any hop of the redirect chain, for robots.txt or the page, lands on a parking or marketplace host on a fixed list (GoDaddy, Namecheap, Dynadot, Porkbun, Sav, Epik, Spaceship and Flippa count only on their sale paths), or moves to a ww-and-digits host of the same domain, or ends on the path /lander. A marketplace listed as itself is not flagged. (c) A 2xx page carries a sale, parking, expiry or registrar placeholder phrase from a fixed list (counted only on pages under 1,000 words), or loads AdSense for Domains (caf.js), or has a script, link or form address on a parking or marketplace host. Hand-check before the parked share is trusted: 50 detections and 50 non-detections are drawn in key order (non-detections among links that answered with a page, the states where a parked page could hide) and each is read in full and judged parked or for sale, or not. Both counts are shown. If more than 5 of the 50 detections are wrong, or more than 5 of the 50 non-detections are parked pages the detector missed, the parked column carries that result beside it and reads as not yet trusted.

### Years since the last change (fixed now)
The first capture of the newest distinct version of the address that the Wayback Machine holds (200 captures, collapsed on digest). For an address that answers today, the value counts only when today's bytes equal that version. Otherwise it reads "changed since the archive's newest version". The Last-Modified header is recorded when a server sends one and ignored when it is within one day of our read. Per sample and era, for live states: the number of live pages with a dated version, the median years with a distribution-free 95% interval for the median (order statistics), and the share of live pages unchanged for at least 10 years with a Wilson 95% interval. The own-name and landmark tables show the value for every row, with the first 200 capture date.

### Ruler (fixed now)
For each sample and era, the share of each state with a Wilson 95% interval, over all units read in that cell. NOTHING_RETURNED is its own column and no state is folded into another. A cell with fewer than 30 units read shows its counts and is marked too few to read as a share. These samples carry no outcome threshold. They are descriptive. A difference between two cells is read only when the two intervals do not overlap and the gap is larger than the repeat floor. Otherwise it reads cannot tell.
Repeat floor: units whose key starts with 0, 1 or 2 (about 3 in 16) are read a second time at least three hours after their first read, by the same code, reusing the stored baseline. Flips are counted item by item, by pair of states, and the flip share carries a Wilson 95% interval.
Known-good gate: early/gate.py, 22 offline self-tests and 11 controls (one per state), run before every pass. If any reads wrong, the pass reads nothing and the summary says the instrument failed its gate.

### Public surfaces (fixed now)
Aggregate shares per sample and era, a small table of examples per sample, the own-name table and the landmark table. Examples: per sample, the six units with the smallest keys among those read, after removing addresses with a personal-page marker (a tilde, or a path segment people, users, user, staff, faculty, homes, home, members, personal, students or student) and addresses on personal hosting services (geocities.com, tripod.com, angelfire.com, members.aol.com, home.earthlink.net, fortunecity.com, xoom.com, homestead.com, blogspot.com, wordpress.com, livejournal.com). Examples are plain text, not links. Never registrant data, never prices, no sale-listing links, no commentary on any domain or owner. Readings defined after the data are labelled as such.

### Not claimed
Whether a page that answers holds what the listing meant. Whether a dead address was taken down on purpose. Who owns any domain. A host that refuses automated readers can read DEAD_HTTP (401, 403 or 429) or ROBOTS_DISALLOWED, and both are shown apart. One seat (this Mac).

Note 4 (9 Nov 2026, after a 12-address trial pass of the samples in Addendum 3, before the main pass): a site that sets a cookie and sends the reader back to the same address read as a redirect loop, because our reader kept no cookies. A browser keeps cookies within a visit, so each read now keeps its own cookie jar for the length of that read and discards it afterwards. The 12 trial reads are set aside (data/early/reads_trial_discarded_20261109.json) and read again in the main pass. No state, threshold or draw changed.

## Addendum 4 (9 Nov 2026, written before any landmark frame was built or any landmark read): landmarks of the early web
Sample L1 lists famous sites of the 1990s and 2000s from public lists, by rule and not by hand. A site counts when a source lists an address that points at the front page of a domain of its own: the host is the registered domain (ICANN section of the Public Suffix List) or www. plus it, the path is empty, "/" or an index file (index, default or home, with .html, .htm, .shtml, .php or .asp), and there is no query. Deep links and sites on someone else's domain (a page on a hosting service, a video on a video site) do not count. Unit: one registered domain, whatever its sources. The address read is the front-page address as first listed. Era: the year it was first listed by any source, in the bins 1994 to 1996, 1997 to 2001, 2002 to 2008, and 2009 and later.
Sources. (1) Wikipedia: "List of Internet phenomena" on English Wikipedia through the MediaWiki API, the last revision before the first day of each month from May 2004 to January 2010, and the current revision. Links inside ref tags, citation templates and comments are removed first. A domain from the monthly revisions counts if it appears in at least two of them, so a link that lasted only days does not count. A domain in the current revision counts on that one revision. (2) Webby Award winners for the ceremonies of 1997 to 2008, as published on the Webby Awards' winners pages, read from their Wayback Machine captures or the current winners archive (landmarks/scout_webby.py states the pages). Winners only, never nominees. (3) Yahoo! Picks and Cool Site of the Day: every pick page in the Wayback Machine's index for the columns' archive paths, each read at its earliest 200 capture, picks taken from inside the dated entries (landmarks/scout_picks.py states the paths and the rule that tells a pick from navigation). If a source cannot be read in full, the pages read are listed and the coverage is stated beside the rates.
Draw: every unit, read in key order (the seed of Addendum 3), so a partial pass is a random draw. States, ruler, detector, repeat floor and gate are those of Addendum 3, and the table shows, per site, its state, the years since its content last changed and the date of its first 200 capture. The public table names the sites, because they are famous public sites and the list is the point. No owner data, no prices, no commentary.
Readers' suggestions: Wayfinder named boredatwork.com, yourethemannowdog.com and badgerbadgerbadger.com before this rule was written. Whether each comes out of the rule is checked after the frame is built. Any that does not is read by the same rules in a separate bin labelled suggested by readers, at the address as given (http://<domain>/), and never enters the landmark rates.

Note 5 (9 Nov 2026, before any repeat read or hand-check draw, during the first pass): each sample's draw keys are the smallest keys of a much larger frame, so they all begin with 0. Three consequences follow. Links are read sample by sample, the DMOZ sample first, rather than interleaved, which leaves each sample's own order random. The repeat-floor rule (key starting with 0, 1 or 2) takes every unit of the NCSA, DMOZ, RFC and Federal Register samples rather than about 3 in 16. We keep that rule as written, so those samples are read twice in full, and the landmark sample, whose keys span the whole range because every unit is read, gets about 3 in 16. A hand-check drawn in key order would fall on the DMOZ sample alone, so the parked hand-check instead takes the first 50 detections and the first 50 non-detections in the order of a second key, SHA-256 of seed, the word handcheck and the unit id, which spreads the draw across samples. No state, threshold or sample changed.

Note 6 (9 Nov 2026, before anything from these samples is published): random addresses carry file and folder names, and those can name a person or a group. On the page, each example address is shown as its scheme and host, with the rest of the address shortened to a slash and an ellipsis.
