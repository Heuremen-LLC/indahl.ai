STANDARDS

Claim Codes

  • F1 Self-built reference. Results are compared with a reference built from the same setup or from IBM’s stated figures.
  • F2 Selected result. The headline figure is a selected value: a maximum over rows, a best case, or a projection.
  • F3 Reading without a width. A bounded reading is stated as yes or no, without an interval.
  • F4 Reading not released. A reading needed to recompute the claim is not in the paper or its files: run dates, counts, circuits or intervals.
  • F5 Number recomputes differently. A printed number does not follow from the paper’s own data or arithmetic.
  • F6 Text differs from own table. The text, abstract or caption differs from the paper’s own table, figure or files.
  • F7 Classical comparison available. A simple classical method on the same instances matches or exceeds the reported result.

Faults

The baseline built after the measurement it judges

  • FLT-01 The baseline averaged, counted or searched differently from the measurement
  • FLT-02 A fixed threshold against a statistic that grows with n
  • FLT-03 A maximum over many draws reported as a measurement
  • FLT-04 The in-sample fit, including its most disguised form
  • FLT-05 A continuum assumed where only discrete values were reachable
  • FLT-06 Dependent observations counted as independent
  • FLT-07 Time-asymmetric differencing
  • FLT-08 A per-unit constant read as signal
  • FLT-09 An unequal setup across the columns being compared
  • FLT-10 Saturated or censored cells averaged as data
  • FLT-11 One artifact's internal record used as a second, independent reading
  • FLT-12 The pilot that came out perfect

Zeroing a gap that was itself the reading

  • FLT-13 Calibrating away the difference between two seats
  • FLT-14 Forcing agreement between quantities that cannot be commensurate

The fold that erases the discarded half

  • FLT-15 A magnitude taken where the last step produced two numbers
  • FLT-16 A sum assumed where two effects multiply
  • FLT-17 Asking which way a sign points instead of whether it holds
  • FLT-18 A snapshot that keeps the value and throws away the trajectory

The forced verdict, and the answer that was never offered

  • FLT-19 A ruler that cannot say “I cannot tell” lies at scale
  • FLT-20 The two-answer question that has three answers
  • FLT-21 Four outcomes collapsed into two
  • FLT-44 A result that does not resolve, filed as a null

The instrument that is wrong about itself

  • FLT-22 You will report a count about yourself from memory
  • FLT-23 Your own checker will be wrong, and all in one direction
  • FLT-24 Every count has a ruler hidden inside it, and the rulers disagree
  • FLT-25 A verdict without a width is not a verdict
  • FLT-26 Two of your three seats are the same seat
  • FLT-27 A reviewer handed no evidence is measuring your tone
  • FLT-28 The same fault counted as five successes

The claim that was never checked

  • FLT-29 An equals sign is a claim, and you will print one you have not checked
  • FLT-30 A fabricated number passes every check that reads shape
  • FLT-31 Counting mentions and reporting it as measurement
  • FLT-32 Fitting a sequence whose points are on different axes
  • FLT-33 Computing the significance before checking the literature
  • FLT-34 A pattern found twice is a pattern, not a law
  • FLT-35 The correspondence with the deepest history proves the least
  • FLT-36 The relationship the whole structure rests on is not a constant

State, staleness, and work you cannot see

  • FLT-37 Something long-lived is holding an old copy of what you just changed
  • FLT-38 The absence of a process is not the absence of work
  • FLT-39 Your test data will become a finding about innocent work

When the guard becomes the deliverable

  • FLT-40 Naming the gap becomes the whole transaction
  • FLT-41 Writing a failure mode down did not stop it
  • FLT-42 A rule from a single instance given a theorem's authority
  • FLT-43 Narrating the mechanism instead of using it
  • FLT-45 Explaining the work instead of stating it

Guards

Procedures that run before the work

  • GRD-01 The ruler is chosen before the quantity is computed
  • GRD-02 Reference material is loaded hot, not summarised
  • GRD-03 The baseline is constructed and written down first
  • GRD-04 The instrument is tested as an object before it is pointed at anything
  • GRD-05 Per-unit constants are removed, not caveated
  • GRD-06 The setup is equalised across every column being compared

Procedures that run during the work

  • GRD-07 Exact nulls in preference to resampling, wherever one exists
  • GRD-08 Four outcomes, never two, and the terminating reason on every call
  • GRD-09 Every reported figure carries its own n, and the n it was selected from
  • GRD-10 Saturated cells are counted before anything is aggregated
  • GRD-11 Dependence is priced by independent units, not by rows
  • GRD-12 One event is read from three seats, never two
  • GRD-13 An absence gets the same scrutiny as a presence

Procedures that run on the output

  • GRD-14 The row is written at the moment of the catch, before the corrected number is stated
  • GRD-15 A dropped arm is named in the tool's own output, not quietly replaced
  • GRD-16 The wrong first reading is published beside the corrected one
  • GRD-17 Every report closes with four parts
  • GRD-18 Writes are guarded by assertions that block partial application
  • GRD-19 Loops are bounded, and long work is not held open by a session
  • GRD-20 Retained rules carry what they rest on

Procedures against the instrument being wrong about itself

  • GRD-21 Any count about your own behaviour is read from the record, never from memory
  • GRD-22 Every rate states its denominator
  • GRD-23 A detector remembers what it has already flagged
  • GRD-24 The third seat must be able to disagree
  • GRD-25 The outside reviewer is handed the evidence, or its verdict is discarded
  • GRD-26 Values get a separate check from structure
  • GRD-27 Both sides of every identity are evaluated before it is printed
  • GRD-28 The prior-art check runs before the significance calculation, not after
  • GRD-29 Units are checked across every point before anything is fitted
  • GRD-30 A load-bearing relationship is re-read live before anything stands on it
  • GRD-31 After any change, the value is re-read through the path that consumes it
  • GRD-32 Liveness is checked by recent completed work, never by a running process
  • GRD-33 Test writes go somewhere the live path does not read
  • GRD-34 A named gap is fixed if fixing is cheaper than describing it
  • GRD-35 A residual bin is refused by the scorer, not avoided by the scorer's author
  • GRD-36 The catalogue's families ride in front of every exchange, read live from the published source
  • GRD-37 The diagnosis and the replacement instrument ship in the same document
  • GRD-38 The ruler is named in the output, beside the number
  • GRD-39 Business copy passes a tone gate that refuses persuasion

Recount Requirements

  • REQ-01 Name the ruler before the number
  • REQ-02 Write the baseline down first
  • REQ-03 State the data source
  • REQ-04 State the version read
  • REQ-05 Use reading outcomes
  • REQ-06 Give each reading its interval and level
  • REQ-07 Test the instrument first
  • REQ-08 Publish receipts
  • REQ-09 Name dropped material
  • REQ-10 Publish corrections beside the first reading
  • REQ-11 Keep CANNOT_TELL as its own result
  • REQ-12 State what was not tested
  • REQ-13 Print the counts beside every headline share
Process

Each code and fault is read as PRESENT, ABSENT, CANNOT_TELL, NOT_APPLICABLE, APPLIED, NOT_APPLIED. Each reading is ABOVE, BELOW, CONSISTENT, CANNOT_TELL.
