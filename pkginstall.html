PKGINSTALL · Stated Install Command Against Resolution

Does the install command a project gives work today?

The description of a PyPI project usually tells the reader to run pip install and its name. For the most downloaded projects this page takes the first such command, keeps it only if it names the project, and asks pip whether it could install it today on a fresh Python 3.12. The check is a dry run on wheels only, so no project's code is run. Projects with no command, a command with other options, a path or URL, a placeholder, or no wheel that fits are not comparable and are counted apart.

The plan, with two dated addenda and a note, was committed before the first project was read. Both addenda came from hand checks before anything was shown: a placeholder the reader did not recognise, and commands that install something other than the project. Both changed the reading and the whole read was run again each time.

Named here and want to answer a row? Respond

Agree: pip would install the command. Disagree: pip fails because a target is not on PyPI, the requirements conflict, or no version matches although the project has a wheel that fits. Fewer than 30 comparable projects reads cannot tell. A command that works says nothing about whether the project works. Source: the PyPI JSON API and pip.

Plan, code and trend history for this page are public: pkginstall. Every plan was committed before the data it describes.

Software this page uses or compares against: pip (git · PyPI).
