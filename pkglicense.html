PyPI projects state a license that differs from the license GitHub reports for their repository. We read each in full. 4 of them are a classifier that differs from the license field, or a package in a subfolder of a repository with another root license.

Division: IRIS

Is the license a package states the license of its repository?

A package on PyPI states its license in its metadata. The repository it points to carries a license file. For the most downloaded projects this page compares the two, as GitHub detects the repository's license, and groups each pair as agree, disagree, or not comparable. Projects with no GitHub repository, no stated license, or a repository license GitHub cannot identify are not comparable and are counted apart.

Every disagreement was read in full, both sides, before it was shown, and the reason is written beside it. The plan, with its two dated addenda, was committed before the first project was compared. The page does not say which side is right.

The outcome is read under Faults and Guards 2.0 from 12 November 2026, with the rule in the plan addendum dated that day. The share of disagreements is read against zero. It reads ABOVE when its whole 95 percent interval is at or above 0.05, CONSISTENT when the whole interval is below 0.05, and otherwise CANNOT_TELL with a reason. An interval that holds both 0 and 0.10 reads CANNOT_TELL (TOO_WIDE_TO_RESOLVE). Fewer than 30 comparable rows also read CANNOT_TELL (TOO_WIDE_TO_RESOLVE). Beside each share the page prints the count of failed reads and the share of CANNOT_TELL split by reason.
